# Read-only обнаружение Keenetic (#76)

`mors_adapters::keenetic::discover` читает существующие интерфейсы и локальный
манифест установленных компонентов. Linux-источник `LocalKeenetic` использует
только GET `http://127.0.0.1:79/rci/show/interface` и чтение `/etc/components.xml`.
Redirects и proxy из окружения отключены; connect timeout 2 секунды, общий timeout
5 секунд, каждый ответ ограничен 1 MiB. Ошибки не содержат тело ответа.

Результат отделяет `state` (административное состояние), `link`, `connected`,
явный ID и `interface-name`. Отсутствие поля сохраняется как `None`/`Unknown`;
имя объекта из ключа JSON не заменяет ID. Нет подстановки `t2s21`, вывода роли
по имени/описанию, версии IKE, ASC или IPsec по одному типу. Неизвестный тип
остаётся неизвестным. HTTP, семантическая ошибка RCI даже при HTTP 200,
malformed response, ошибка транспорта и превышение лимита различаются.
Повреждённый ответ не возвращает частичный список. Ошибка манифеста компонентов
сохраняется отдельно и не превращается в «компоненты отсутствуют».

## Классификация и дальнейшие границы

`VpnNeedsValidation` означает только поддерживаемое семейство протокола.
Это не разрешение добавить интерфейс в пул: клиентская роль, Internet egress,
принадлежность и явное принятие должны быть проверены последующими адаптерами.
В частности, PPTP/L2TP провайдера, WireGuard server/site-to-site и IKE с
неизвестной ролью не получают допуск по типу, `defaultgw`, `global` или `up`.
Явные server-типы отделяются; неизвестные варианты server-типа остаются
`Unknown`. PPPoE, модемы и upstream-типы выделены отдельно, OpenVPN вне охвата.

Любой `Proxy`, включая имя `Proxy21` и описание Mors, требует проверки
принадлежности. Компонент `proxy` в манифесте не подтверждает готовность внешнего
NaiveProxy/CA, TCP probe или пользовательский UDP: readiness остаётся Unknown,
UDP NaiveProxy — Unsupported по контракту протокола.

Адаптер не пишет реестр/конфигурацию, не выбирает active, не запускает процессы,
не вызывает up/down/reset, install/commit и legacy scan с hook. Shell setup и
его decision lock #57 сохранены. Подключение к мастеру, подтверждение роли по
конфигурации конкретного VPN и lifecycle остаются в последующих задачах
#77/#79–#93; миграция legacy выходов — #97/#98. Новый публичный CLI здесь не вводится.

## Проверка и происхождение fixtures

Fixtures — синтетические минимальные контракты, без реальных имён, адресов,
описаний или секретов. `interfaces-3-array.json` покрывает старую array-форму
из существующих setup_plan tests; название не означает проверку на OS 3.
`interfaces-5-map.json` покрывает object-форму. VPN/server-строки — негативные
и пограничные примеры, не свидетельство наличия этих типов на тестовом роутере.

27.09.2026 выполнено только чтение формы `/rci/show/interface` и
`/etc/components.xml` на disposable NC-1913 (OS 5.0.12). Подтверждены object-форма,
отдельные `state`, `link`, `connected` (yes/no), пропуски полей и структура
`components/component/name`. Сырые ответы в репозитории не сохранялись.
Это проверка схемы; Rust-бинарник на роутере не запускался и матрица остальных
версий/моделей этим не подтверждается.

Контрактные тесты покрывают offline/неполные интерфейсы, чужой Proxy, WAN,
неизвестные типы, отсутствие компонентов, HTTP/semantic errors, malformed JSON/XML,
DTD, лимиты, неизменность системного имени и отсутствие принятия под управление.
Локальный HTTP fixture проверяет фактический GET, запрет redirect, усечение
ответа и ограничение памяти транспорта.

Итог локальной проверки 27.09.2026: `scripts/qa/rust.sh` — PASS (fmt,
Clippy `-D warnings`, workspace tests, doc tests, release build); 12 новых
тестов обнаружения/HTTP и прежний тест контракта NaiveProxy — PASS.
`scripts/qa/static.sh` (включая ShellCheck/actionlint) — PASS;
`bats tests` — 508/508 PASS. Проверки выполнены в Linux-контейнере на снимке
актуального main `7746eda` с изменениями #76; LF и исполняемые биты сохранены
