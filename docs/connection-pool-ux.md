# Единый UX управления подключениями

Нормативное расширение [дизайн-системы CLI](cli-design-system.md).
Задача: [#65](https://github.com/ivni/mors/issues/65), 25.09.2026.
Статус: целевой интерфейсный контракт, **команды ещё не реализованы**.
База сверки: актуальный `main`, `e220b281c603d126ba4f424fac57fedaf289f55a`.
Основания: [REQ-CORE-001–021](connection-core-requirements.md),
[ADR-0001](adr/0001-connection-core-boundaries.md).
Runtime, help, package version, роутер и decision lock #57 не изменяются.

## 1. Область и словарь

Подключение — сохранённый VPN/прокси-профиль с постоянным ID, типом и
владением. Пул — управляемые подключения разных типов. Активный выход
обслуживает новые защищаемые сессии; он один либо отсутствует. Старые сессии
на выводимом подключении и проверки резервов не создают второй active.
Слово «протокол» в экране обозначает тип/вариант подключения, а не engine.
Xray и NaiveProxy runtime показываются отдельно в подробностях.

Охват задаёт REQ-CORE-002: NaiveProxy, VLESS/Xray, Shadowsocks и перечисленные
там штатные VPN Keenetic. Наличие типа в меню не доказывает поддержку операции
на конкретной OS/ABI. OpenVPN исключён; существующие настройки сохраняются,
миграция установки с выбранным OpenVPN останавливается до изменения рабочего
состояния и предлагает выбрать поддерживаемый выход. Direct не включается.

Пользователь видит независимые признаки, которые нельзя свести к `enabled`:

| Поле | Коды / русский текст | Смысл |
| --- | --- | --- |
| `ownership` | `external` / ОБНАРУЖЕНО; `managed` / ПОД УПРАВЛЕНИЕМ | Обнаружение не разрешает изменение чужого VPN. |
| `participation` | `included` / УЧАСТВУЕТ; `excluded` / НЕ УЧАСТВУЕТ | Намерение пользователя разрешить выбор; не команда запуска/остановки. |
| `admission` | `unconfirmed` / СОХРАНЕНО, НЕ ПОДТВЕРЖДЕНО; `ready` / ДОПУЩЕНО; `blocked` / ДОПУСК ЗАБЛОКИРОВАН | Готовность конфигурации, capabilities и подтверждений. Сетевая ошибка нового профиля не разрешает выбор. |
| `health` | `unknown` / НЕ ПРОВЕРЕНО; `checking` / ПРОВЕРЯЕТСЯ; `healthy` / ИСПРАВНО; `unstable` / НЕСТАБИЛЬНО; `unavailable` / НЕДОСТУПНО; `stale` / ПРОВЕРКА УСТАРЕЛА | Здоровье текущей ревизии, отдельно от запуска процесса. |
| `runtime` | `unknown` / НЕИЗВЕСТНО; `stopped` / ОСТАНОВЛЕНО; `starting` / ЗАПУСК; `running` / ЗАПУЩЕНО | Наблюдаемое состояние backend; `running` само по себе не означает исправный выход. |
| `role` | `active` / АКТИВНО; `standby` / РЕЗЕРВ ГОТОВ; `draining` / ВЫВОДИТСЯ ИЗ РАБОТЫ; `none` / НЕ ВЫБРАНО; `unknown` / РОЛЬ НЕ ПОДТВЕРЖДЕНА | Текущая роль, а не сохранённое предпочтение. |
| capability | `supported` / ПОДДЕРЖИВАЕТСЯ; `unsupported` / НЕ ПОДДЕРЖИВАЕТСЯ; `unknown` / НЕ ПОДТВЕРЖДЕНО | Для каждой операции и TCP/UDP/DNS/drain отдельно, с причиной и действием. |

`invalid_config` отображается как ОШИБКА КОНФИГУРАЦИИ с `admission=blocked`.
Неподдерживаемый UDP NaiveProxy не является сетевой неисправностью TCP.
`standby` требует managed + included + ready, свежего здоровья текущей
ревизии и готовности выбрать выход без недостающих согласий/компонентов.
Профиль, который ещё нужно запустить и проверить, не считается готовым резервом.
Конкретные сроки свежести и resource budgets принадлежат #70/#75/#117;
экран использует полученные от ядра `freshness` и `valid_until`, не придумывает
собственный порог. После reboot или внешней правки старое здоровье не актуально.

Состояния всего пула: `unconfigured` / НЕ НАСТРОЕНО; `starting` / ЗАПУСК;
`healthy` / РАБОТАЕТ; `degraded` / БЕЗ ГОТОВОГО РЕЗЕРВА;
`switching` / ПЕРЕКЛЮЧЕНИЕ; `unavailable` / НЕДОСТУПНО;
`direct_fallback` / ПРЯМОЙ РЕЗЕРВ; `paused` / ПРИОСТАНОВЛЕНО;
`unknown` / СОСТОЯНИЕ НЕ ПОДТВЕРЖДЕНО. Lifecycle и причина общего upstream
сбоя показываются отдельно. `healthy` означает подтверждённый active и хотя бы
один готовый резерв; `degraded` — исправный active без такого резерва.

## 2. Экраны статуса и управления

Все примеры вымышлены, числа иллюстративны. Макеты — требования к будущему CLI.

```text
Подключения: РАБОТАЕТ
Сейчас используется: «Основной» — NaiveProxy
Сайты через TCP работают. UDP заблокирован:
часть игр и звонков может не работать.
DNS для выбранных сайтов защищён
Проверено: 8 секунд назад. Резервов готово: 1 из 2 участвующих.
Прямой резерв: запрещён
Последняя смена: 25.09 12:00, c02 → c01
Причина: подтверждённый сбой c02

1. Основной     NaiveProxy   АКТИВНО
2. Запасной     WireGuard   НЕДОСТУПНО
3. Второй       VLESS       РЕЗЕРВ ГОТОВ
4. Новый        Shadowsocks СОХРАНЕНО, НЕ ПОДТВЕРЖДЕНО

Можно проверить «Запасной»: выберите 2, затем «Проверить».
[1–4] Подключение  [A] Добавить
[D] Найти существующие VPN  [Q] Выход
```

Знаменатель резервов включает участвующие неактивные управляемые профили,
даже если они временно неисправны; исключённые и неподтверждённые не входят.
При паузе/общем отказе active отсутствует; прямой резерв не получает ID VPN.
При stale snapshot экран явно пишет «Последние известные данные», не показывает
старый active как текущий, указывает время snapshot и следующее действие.
Восстановление прежнего выхода делает его резервом: автоматического failback
и переключения ради меньшей задержки нет. Общий upstream failure не вызывает
перебор VPN и выводится как «Нет доступа к интернету; проверьте WAN».

Карточка сначала показывает имя, протокол, понятный итог, время проверки,
причину и ближайшее полезное действие. В разделе «Подробности» доступны ID,
владение, участие, допуск, runtime, роль, TCP/UDP/DNS и классифицированная
причина. Эти признаки сохраняются независимо, но не превращаются в обязательную
анкету для пользователя. Меню:

```text
«Запасной» — WireGuard: НЕДОСТУПНО
Сервер не ответил. Проверено в 12:01:02.
Настройки сохранены. Можно проверить ещё раз.
[1] Проверить  [2] Изменить настройки
[3] Не выбирать автоматически
[4] Использовать сейчас  [5] Остановить VPN
[6] Удалить  [7] Переименовать
[8] Подробности  [Q] Назад
```

Недоступное действие остаётся объяснимым: причина + инструкция вместо
молчаливого исчезновения или ошибочного обещания поддержки. Для external
доступны просмотр, read-only обнаружение и «Принять под управление».
Имя не служит идентификатором владения. При неоднозначном имени TTY показывает
список совпадений; noninteractive требует ID или однозначное имя.
Правила сравнения имён сохраняются из §5 дизайн-системы.

Для терминала шириной 40 столбцов таблица превращается в последовательность
карточек с переносом по словам; ID, состояние и следующее действие не обрезаются.
Длинное имя переносится, управляющие символы очищаются. При `NO_COLOR`, pipe,
redirect и `TERM=dumb` нет ANSI/cursor control, смысл идентичен. Без TTY
команда без аргументов выдаёт статус, не меню. `--json` всегда отключает меню,
цвет, прогресс и любые запросы ввода.

### 2.1. Выбор без запоминания имён

Из главного меню доступны все обычные действия без ввода команд и флагов.
Если действие вызвано напрямую без объекта, например `mors connection remove`,
интерактивный CLI открывает тот же выбор. Человек никогда не обязан переписывать
название, различать похожие символы или искать ID для обычного управления.
Это относится к show/update/rename/enable/disable/activate/start/stop/remove,
adopt и возврату в мастер. Check без аргументов сохраняет проверку active;
другой объект выбирается из карточки. Технические ID остаются для автоматизации.

- Каждый вариант имеет видимый номер, имя, тип и краткое состояние; активное
  подключение дополнительно отмечено словами «используется сейчас».
- Сначала показываются подходящие объекты. Недоступные для действия видны
  отдельно с причиной и способом её устранения, но не выбираются как пригодные.
- Один вариант не применяется автоматически. Нулевой список сообщает
  «Нет подключений для удаления» или соответствующую причину, предлагает
  «Назад», а при уместности — «Добавить» / «Найти существующие VPN».
- Длинный список имеет страницы и необязательный поиск по части имени;
  поиск никогда не становится обязательным. Видны номер страницы и команды
  перехода. Номера относятся к показанной странице и не являются ID.
- Некорректный номер оставляет пользователя в том же списке с подсказкой
  допустимого диапазона. Выбранные ранее корректные параметры не теряются.
- Выбор закрепляется за ID и ревизией показанного объекта. При обновлении
  inventory нельзя применить тот же номер к другому объекту: список обновляется,
  изменение объясняется, выбор/план подтверждаются заново.
- Enter в списке ничего не выбирает; Q возвращает назад. В подтверждении
  Enter означает «нет». В меню всегда написано, куда ведёт «Назад» или «Выход».
- `--yes` без селектора не выбирает первый/единственный объект и не разрешает
  массовую операцию. В pipe/JSON отсутствие обязательного селектора даёт `64`
  с подсказкой `list` или `discover`; интерактивного ожидания нет.

### 2.2. Удаление и понятные последствия

Пример полного пути для неактивного профиля, созданного в Mors:

```text
Что удалить?
1. Основной — NaiveProxy, используется сейчас
2. Запасной — WireGuard, резерв готов
3. Старый — VLESS, не используется
Q. Назад
Ваш выбор: 3

Удалить подключение «Старый» (VLESS)?
Его настройки и сохранённые реквизиты будут удалены.
Работающее подключение «Основной» не изменится.
Автоматически отменить удаление нельзя.
Если хотите оставить настройки, выберите «Не выбирать автоматически».
Удалить? [y/N] (да/нет; Enter — нет)

Подключение «Старый» удалено.
[1] К списку подключений  [Q] Выход
```

Не требуются точное имя, ID, повторное название или слово DELETE. Выбор строки
не является подтверждением удаления. Для принятого VPN экран отдельно пишет
«Будет удалена также настройка этого VPN в Keenetic». Для активного — называет
новый выход и судьбу текущих соединений; при отсутствии резерва объясняет,
что выбранные сайты станут недоступны. Текст о сохранении работающего выхода
допустим только если это подтверждено планом. Массовое удаление здесь не вводится.
При отказе результат «Удаление отменено. Ничего не изменено» возвращает
в карточку; повторного ввода объекта не требуется.

Первый экран не требует понимания слов admission, runtime, drain, backend,
capability, snapshot и fail-closed. «Не выбирать автоматически» поясняется
«Настройки останутся; Mors не будет использовать это подключение для новых
соединений». «Остановить VPN» поясняет влияние вне Mors. Состояние «Без готового
резерва» сопровождается «Сейчас всё работает, но при сбое переключиться некуда».
Технические названия протоколов сохраняются с кратким объяснением ограничений.
Подробности и точная команда для автоматизации доступны, но не обязательны.

Восстановление из ошибки в TTY предлагает доступные пункты «Повторить проверку»,
«Изменить настройки», «Продолжить настройку», «Назад», а не только строку
команды для копирования. Выполняемая операция показывает текущий этап и итог;
повторное нажатие не создаёт дубликат операции. Ctrl+C до применения отменяет
действие, после начала транзакции прекращает ожидание, но не обещает откат:
CLI сообщает, как увидеть результат через меню статуса. Безопасность прерывания
и восстановления определяется координатором.

## 3. Добавление и исправление

Мастер: тип → capability preflight → имя и безопасный ввод параметров →
локальная валидация → сохранение вне выбора → изолированная проверка →
показ результата и ограничений → явный допуск → при желании активация.
Сеть проверяется без замены действующего выхода; если изолированный probe
не подтверждён для backend, шаг блокируется с объяснением, а не выполняется
через active с ложным успехом. Отмена до сохранения ничего не создаёт;
после сохранения сообщает ID и оставляет неподтверждённый профиль.

Мастер задаёт по одному вопросу, показывает понятное название текущего шага
и позволяет вернуться к предыдущему без потери корректного ввода. Известные
варианты (тип, найденный VPN, действие) выбираются из списка. Пользователь
может начать с «У меня есть ссылка» или «VPN уже настроен в Keenetic»:
известный формат ссылки определяет тип, затем показывает его для подтверждения;
при неизвестном формате предлагается список типов без печати введённого секрета.
Имя предлагается из безопасного названия ссылки или как «Подключение 1»
с подбором свободного номера; ручное переименование необязательно.
Существующие реквизиты при редактировании не нужно вводить повторно: явный
выбор «Оставить прежние / Заменить» не показывает секрет. Ошибка поля объясняет
ожидаемый формат рядом с этим полем и не сбрасывает весь мастер.
После успешной проверки доступны «Разрешить автоматический выбор», затем
«Использовать сейчас» или «Оставить резервом» — без выхода в командную строку,
с теми же отдельными подтверждениями и gates, что у enable/activate.

```text
Подключение c04 сохранено, но не подтверждено.
Причина: сервер не ответил за время проверки.
Сохранено: рабочий выход c01 не изменён; c04 не участвует в выборе.
Действие: исправьте параметры или повторите mors connection check c04.
[1] Изменить  [2] Проверить снова  [3] Удалить  [Q] Выйти
```

Синтаксически невалидный ввод не заменяет конфигурацию. Корректный новый
профиль после сетевой ошибки остаётся доступен для редактирования и повторной
проверки (REQ-CORE-012). Успешный `check` сам по себе не включает участие.
Для update действующего профиля используется кандидатная ревизия: ошибка
не заменяет рабочую ревизию, результат отдельно сообщает судьбу кандидата.
Внешняя правка уже управляемого VPN принимается как новая наблюдаемая ревизия,
сбрасывает старую оценку здоровья и требует повторной проверки. Старые значения
не восстанавливаются поверх правки пользователя. Конфликт ревизии между
подтверждением и применением отменяет устаревший план и требует нового просмотра.

NaiveProxy принимает `naive+https` через ввод без эха либо защищённый файл;
URI/пароль не попадают в argv или вывод. Полный URI никогда не печатается даже
при ошибке парсинга. После проверки синтаксиса выполняются source-bound
TCP/TLS/auth и проверка выхода; затем отдельно проверяются защищённый DNS,
bootstrap/no-loop и UDP fail-closed. Один TCP-успех не означает готовую активацию.
До включения в выбор (включая будущий автоматический выбор) показывается:

```text
NaiveProxy передаёт только TCP.
Защищаемый UDP будет заблокирован; часть игр и звонков может не работать.
Прямой обход не включается. DNS должен иметь проверенный защищённый путь.
Разрешить этому подключению участвовать в выборе? [y/N]
```

Согласие связано с ID, текущей конфигурацией и версией предупреждения.
Изменение транспортных ограничений или конфигурации аннулирует допуск до
повторной проверки и согласия. В noninteractive необходимы
`--ack-tcp-only --yes`; один `--yes` недостаточен. Согласие не снимает
capability, DNS/UDP, платформенные и ресурсные gates ADR. После автоматического
выбора статус повторяет TCP-only и блокировку UDP. Direct policy подтверждается
совершенно отдельным действием; `UDP ASSOCIATE` не предлагается как настройка.

## 4. Значение действий и подтверждения

| Действие | Результат и безопасное подтверждение |
| --- | --- |
| Включить участие (`enable`) | После свежей проверки/допуска разрешает выбор; не обещает смену active. Если нужен запуск/перезапуск, план раскрывает это до применения. |
| Исключить (`disable`) | Исключает проверки/выбор; не останавливает native VPN и не удаляет данные. Для active сначала план смены; старые сессии сохраняются при доказанном drain. Последний выход требует подтверждения и объяснения блокировки защищаемого трафика. |
| Сделать активным (`activate`) | Только included, ready и свежий кандидат; меняет новые сессии после verify/commit. Не включает участие неявно. |
| Остановить VPN (`stop`) | Исключает участие и останавливает управляемый runtime после drain. Настройки остаются. Показывает влияние на клиентов/маршруты Keenetic вне Mors; неизвестное влияние блокирует операцию. |
| Запустить VPN (`start`) | Запускает и проверяет backend, не включает участие и не выбирает active. |
| Удалить (`remove`) | После подтверждения выводит из выбора, останавливает и удаляет профиль, его секреты и точно принадлежащие ему объекты. Для принятого native VPN явно означает удаление конфигурации VPN в Keenetic; это не просто исключение из пула. Чужие/общие объекты не удаляются. |
| Принять (`adopt`) | По стабильному inventory ID и свежей ревизии после показа границ read/update/restore/delete принимает существующий VPN под полное управление, первоначально вне выбора. Не дублирует интерфейс, не меняет его параметры и не выбирает active. Одного read/discover недостаточно. |
| Пауза пула (`pause`) | Останавливает выбор новых защищаемых сессий с закрытым маршрутом; сохраняет намерения участия. Не равна остановке всех VPN или разрешению direct. Resume повторно проверяет выходы. |

Каждая мутация проходит через единственного координатора. До подтверждения
план показывает затронутые ID/ревизии, новый выход, судьбу старых сессий,
сохранение данных и возможную блокировку трафика. По умолчанию ответ «нет».
`--yes` подтверждает только последствия указанного действия. Секреты и endpoint
не входят в план. Отсутствие резервов не разрешает direct автоматически.

```text
Остановить c02 «Запасной» (WireGuard)?
Новые сессии: через c01 после проверки.
Старые сессии: плавная остановка не подтверждена для этого backend.
Будут разорваны также использующие этот VPN соединения вне Mors.
Настройки сохранятся; участие будет выключено.
Без явного согласия остановка не выполняется.
```

Плановый разрыв разрешается только с `--force --yes` либо отдельным
интерактивным подтверждением разрыва. `--force` не обходит проверки владения,
ревизий, recovery, возможностей и допуска. Если drain не поддержан/неизвестен,
обычное действие отказывает без скрытого restart. Если drain подтверждён,
результат может быть `pending`: новые сессии переключены, старые завершаются;
операция имеет ID. По истечении срока ожидания CLI не убивает их автоматически.
Авария не обещает перенос произвольных живых сессий. Recovery-команда выдаётся
координатором для конкретной транзакции, а не заменяется советом выполнить reset.

## 5. CLI и совместимость

Новый namespace **`mors connection` зарезервирован для реализации #101–#108**.
В актуальном [dispatch](../opt/bin/mors) его нет. Примеры ниже не являются
инструкцией к установленной версии. `ID` либо однозначное имя выбирают профиль;
`INVENTORY_ID` выбирает только объект последнего read-only обнаружения.

Грамматика ниже описывает полные вызовы для автоматизации. В TTY без JSON
обязательный селектор можно опустить у действий из §2.1: сначала открывается
список, затем тот же workflow. У update отсутствие `--input-file` открывает
редактор выбранного профиля; rename запрашивает новое имя после выбора;
adopt показывает обнаруженные VPN, wizard resume — сохранённые незавершённые
настройки. В noninteractive эти пропуски возвращают `64`, не догадки.
Выбор в меню только подставляет ID и явные решения пользователя в тот же запрос
координатору; отдельной упрощённой логики применения у мастера нет.

```text
mors connection [--json]
mors connection list|status|events [--json]
mors connection show ID [--json]
mors connection discover [--json]
mors connection add --type TYPE --name NAME --input-file PATH [--json]
mors connection update ID --input-file PATH [--force] --yes [--json]
mors connection rename ID NEW_NAME [--json]
mors connection adopt INVENTORY_ID --yes [--json]
mors connection check [ID|--all] [--json]
mors connection enable ID [--ack-tcp-only] [--force] --yes [--json]
mors connection disable|activate|stop|remove ID [--force] --yes [--json]
mors connection start ID [--force] --yes [--json]
mors connection pause [--force] --yes [--json]
mors connection resume --yes [--json]
mors connection policy direct-fallback on --yes|off [--json]
mors connection wizard resume ID [--json]
```

`add` без параметров открывает мастер только в TTY. Все записывающие команды
без обязательного `--yes` могут спросить подтверждение только в TTY без JSON;
pipe/JSON возвращают `64`. `--force` отдельно никогда не подтверждает действие.
Для update/enable/start он нужен только когда проверенный план требует
разрыва работающих сессий, например из-за перезапуска общего движка.
У add намеренно нет auto-enable/auto-activate: успешное сохранение и успешный
probe не разрешают сменить рабочий выход. Rename меняет только имя.
`check` без селектора проверяет active, `--all` — участвующие профили;
проверить excluded/unconfirmed можно явно по ID. Check обновляет evidence,
но не выполняет ручной выбор или принятие под управление.

В TTY секреты вводятся без эха с восстановлением терминала при прерывании.
Noninteractive принимает профиль только через `--input-file`: регулярный
локальный файл, доступный только владельцу, без следования symlink; содержимое
не копируется в diagnostics. Для NaiveProxy это одна строка `naive+https`;
схемы файлов остальных backend определяют их adapter issues. `--link URI`,
пароль в параметре и произвольные backend flags в новом namespace запрещены.
Ошибки неизвестных аргументов не отражают их значение обратно в вывод.

| Существующий интерфейс | Правило перехода |
| --- | --- |
| `mors vless ...`, §8–10 дизайн-системы | Сохраняются имена, прежние JSON/exit codes и VLESS-область. После handoff — перевод в запрос координатору, без второго selection loop. `vless new` остаётся ошибкой. Legacy `--link` — известный секрет в argv, не образец нового API; переход на безопасный ввод и предупреждение без эха относятся #101/#102/#118. |
| `mors vpn`, `vpn status/set/reset/rescan/scan/net/guest/gateway` | Существующий namespace и сетевые/гостевые функции не переименовываются в управление пулом. После перехода команды, меняющие общий выход, обязаны идти через координатор; `vpn set` не выбирает выход в обход пула. |
| `mors ssr new/port/reset/status` | Legacy имя сохраняется; оно не переименовывает Shadowsocks в новый тип. Изменения управляемого backend идут через координатор после handoff. |
| `mors test`, `setup`, `update`, `rollback`, telemetry | Сохраняют собственные схемы, коды и lifecycle gates; `connection check` их не заменяет. |

Текущий [help](../opt/etc/conf/mors.help) не рекламирует новые команды.
Реализация одновременно обновляет dispatch, help, mutation/JSON guards и
совместимость. Неподдерживаемое legacy-действие после handoff должно явно
отказать с подсказкой, а не обойти ядро. Исправление #57 и lifecycle locking
сохраняются; эта документация не меняет их.

## 6. JSON и коды завершения

Отдельная схема `connection` v1; версии legacy JSON не переиспользуются.
При `--json` stdout содержит ровно один объект, включая syntax/capability/busy
ошибки, stderr пуст, если объект удалось сформировать. Общие поля обязательны:
`schema_version`, `command`, `status`, `exit_code`, `reason_code`, `message`,
`operation_id` (nullable), `next_action` (nullable), `data` (object или null).
`status`: `ok`, `pending`, `cancelled`, `error`. `next_action` содержит
стабильный `code`, русское `message` и безопасный `command` либо null, если
нужно ручное действие вне CLI. Текст никогда не является машинным reason code.

Status data: `pool_state`, `lifecycle_state`, `runtime_current`,
`snapshot_at`, `active_id`, `ready_reserves`, `eligible_reserves`,
`direct_policy`, `last_switch`, `connections` и `operations`. Счётчики резервов
следуют §2. Operations содержит незавершённые операции: `operation_id`,
затронутые IDs, `phase`, `reason_code`, `next_action`; поэтому обычный status
позволяет проверить завершение drain без отдельной неописанной команды.
`last_switch`: `at`, `from_id`, `to_id`, `reason_code` либо null.
Элемент connections: ID, name, protocol, ownership, participation, admission,
runtime, role, health, `config_revision`, `checked_revision`, `checked_at`,
`valid_until`, `freshness`, `latency_ms`, capabilities, reason_code, next_action.
Capabilities имеют `supported|unsupported|unknown` и reason_code для каждой
операции и транспорта. `latency_ms` — целое число либо null, времена — ISO 8601
UTC либо null. Unknown не заменяется нулевой задержкой или старым успехом.
При `runtime_current=false` active_id=null, текущие роли/health неизвестны;
старые данные допустимы лишь в отдельном `last_runtime`, помеченном historical.

Show возвращает одну такую карточку; list/discover — `data.connections`
(external без доказательств не получает ready/healthy; неприменимые участие
и допуск равны null); events — `data.events`
с временем, ID операции, affected IDs и классифицированной причиной.
Мутация возвращает ID профиля, судьбу кандидата и наблюдаемый результат;
pending дополнительно возвращает ID операции и действие `status` для ожидания.
Check возвращает `data.check_state`, выбранные IDs и результаты этапов
`passed|failed|not_checked` с reason_code. Схемы ввода адаптеров и IPC остаются
за пределами этого документа; эти публичные поля — обязательный минимум.

```json
{
  "schema_version": 1,
  "command": "connection enable",
  "status": "error",
  "exit_code": 64,
  "reason_code": "tcp_only_ack_required",
  "message": "Требуется согласие на блокировку защищаемого UDP.",
  "operation_id": null,
  "next_action": {
    "code": "review_tcp_only",
    "message": "NaiveProxy передаёт только TCP. Прямой обход не включается.",
    "command": "mors connection enable c01 --ack-tcp-only --yes"
  },
  "data": {"connection_id": "c01", "changed": false}
}
```

| Exit | Status/list/show/discover/events и мутации |
| --- | --- |
| `0` | Read-only состояние прочитано (даже unavailable) либо операция подтверждена; pending имеет operation_id и не означает завершённое удаление/остановку. |
| `1` | Добровольная интерактивная отмена, без применения нового действия. |
| `2` | Проверка/применение неуспешны; новое подключение могло быть сохранено unconfirmed, прежний выход сохранён/восстановлен. Результат явно различает эти случаи. |
| `3` | Действие неприменимо: busy, missing component, capability unknown/unsupported, stale revision, admission blocked или recovery required; нет нового apply. |
| `4` | Повреждение state/journal либо runtime невозможно достоверно прочитать. |
| `64` | Синтаксис, отсутствие обязательного ввода/подтверждения, EOF вместо ответа. |

Check использует health-коды: `0` healthy; `1` degraded/starting/checking/unstable/
switching; `2` unavailable/direct_fallback; `3` paused/unconfigured;
`4` unknown/stale/неполная обязательная проверка. Для check ID healthy означает
исправность этого профиля, не здоровье пула. Check --all оценивает общий выход
и готовность проверенных резервов. Ошибки аргументов — `64`; запуск невозможен
из-за busy/capability — `3` с `reason_code`, не ложный health-результат.
Незавершённый restore всегда даёт `3` / `recovery_required`, а не `2` с
утверждением «восстановлено». Приоритет — safety/recovery, затем результат
операции. Человек видит, что уже изменилось и что нельзя подтвердить.

Вывод строится по закрытой схеме: никаких URI, endpoint IP, credentials,
raw config/stderr или backend argv. Имена и ID допустимы в локальном интерфейсе;
локальный JSON не является payload телеметрии. Внешний экспорт следует
[отдельному whitelist](telemetry-architecture.md) без raw имён и адресов.

## 7. Недостающие компоненты и диагностика

Instruction-only означает инструкцию к действиям самого пользователя;
Mors не устанавливает компоненты KeeneticOS, не обновляет OS и не открывает
свой web UI. Название недостающего компонента и проверенная инструкция берутся
из capability inventory для конкретной версии OS. Неизвестный компонент
показывается как «Не удалось определить требования», без выдуманного пакета.

```text
Продолжить настройку сейчас нельзя: отсутствует нужный компонент KeeneticOS.
Сохранено: корректные параметры c04; рабочий выход c01 не изменён.
Действие: установите указанный выше компонент в настройках Keenetic.
Это ручное действие может потребовать перезагрузки роутера.
После установки: mors connection wizard resume c04
[1] Проверить готовность снова  [Q] Сохранить и выйти
```

До ввода данных мастер может остановиться на preflight без создания записи.
Если корректные данные уже введены, сохраняется unconfirmed-профиль и номер
шага; секреты — только в secret store. Возврат по ID работает после новой
CLI-сессии/перезагрузки, заново проверяет компоненты, ревизии и capabilities,
не повторяет уже выполненное создание и не возобновляет старое подтверждение.
Noninteractive resume делает preflight и check; если требуется новый ввод,
возвращает `64` с безопасным следующим update/enable, не открывает меню.
Повторная проверка не устанавливает OS или runtime автоматически. Отсутствие
Naive runtime/совместимого ABI объясняется отдельно от компонента Keenetic;
в частности отсутствие допущенного MIPS BE asset блокирует только Naive.

| reason_code | Понятная причина и следующее действие |
| --- | --- |
| `tcp_timeout` | Сервер не ответил: проверить доступность сети и параметры, повторить check. |
| `upstream_unavailable` | Нет интернета на WAN: восстановить WAN, не перебирать профили. |
| `tls_certificate_invalid` | Сертификат сервера не прошёл проверку: проверить имя сервера, срок сертификата и время роутера; не отключать TLS verification. |
| `ca_unavailable` | Нет пригодного хранилища CA: проверить доверенные CA/runtime по инструкции, затем check; не загружать произвольный сертификат автоматически. |
| `authentication_failed` | Сервер отклонил авторизацию: обновить реквизиты через безопасный ввод, затем check; пароль не выводится. |
| `protected_dns_unverified` | Защищённый DNS не подтверждён: исправить DNS по диагностике, повторить проверку; direct DNS не включается. |
| `bootstrap_failed` / `route_loop_risk` | Нельзя безопасно достичь сервера: проверить bootstrap и маршрут WAN; активация заблокирована. |
| `component_missing` / `runtime_missing` | Выполнить instruction-only шаг и resume; сохранённый профиль вне выбора. |
| `capability_unknown` / `capability_unsupported` | Указать конкретную операцию и платформу; unknown требует доказательства, unsupported — подходящего backend/компонента. |
| `revision_changed` | Настройки изменены извне: принять наблюдаемую ревизию, перепроверить и подтвердить новый план. |
| `drain_unavailable` | Плавное действие не подтверждено: отменить или отдельно согласиться на разрыв. |
| `resource_busy` | Не хватает проверенного runtime budget: дождаться drain/операции, затем повторить; живые сессии не убиваются скрыто. |
| `recovery_required` | Операция не завершена безопасно: выполнить точную recovery-команду из результата, новые изменения заблокированы. |

Каждая ошибка дополняется «Сохранено» и «Действие». Закрытые reason codes
могут расширяться с версией контракта; произвольный stderr не подставляется.
Диагностика разделяет TCP health, ограничение UDP, DNS, freshness, capability
и lifecycle. «Порт открыт» не означает «Выход работает».

## 8. Проверяемая приёмка и границы реализации

| Критерий #65 | Контракт и будущий проверочный сценарий |
| --- | --- |
| Русские состояния и пять групп макетов | §1–4, §7: add с timeout → сохранён unconfirmed; исправление → check → отдельный enable; active не заменяется при ошибке. |
| Протокол, active, свежесть, резервы, причина и действие | §1–2, §6: смешанный пул, stale/reboot, внешний edit, upstream failure, auto-switch на Naive. |
| Участие/остановка/удаление/adopt | §3–4: external не изменяется; adopt и stop/remove имеют разный план; гонка ревизии не затирает внешнюю правку. |
| CLI/JSON/codes/совместимость/терминал | §5–6: TTY и noninteractive эквиваленты, missing ack, force без yes, NO_COLOR, ширина 40, один JSON при ошибке; legacy schema неизменна. |
| Управление без запоминания имён и команд | §2.1–2.2, §3, §5: remove/update/adopt без селектора открывают список; неоднозначные и похожие имена выбираются по номеру; rename и исправление не требуют повторного ввода текущего имени. |
| Компоненты и возврат | §7: missing component → ручная установка → resume по ID после reboot, без повторного создания и скрытого OS install. |
| NaiveProxy и понятные ошибки | §3, §6–7: naive+https → TCP check → DNS/UDP gates → ack → enable → activate; TLS/CA/auth ошибки сохраняют рабочий выход, UDP ASSOCIATE не предлагается. |

Перед приёмкой реализации обязательны сценарии с пустым списком, одним
элементом, длинным списком, длинными/похожими именами, обновлением списка
между показом и выбором, неверным номером, Enter, Q и Ctrl+C. Для удаления
проверяются неактивный, активный, последний и принятый из Keenetic VPN:
ни один сценарий не требует перепечатать имя; отмена ничего не удаляет;
устаревший номер не удаляет другой объект; `--yes` без селектора не выбирает
цель. Каждый сценарий повторяется без цвета и при ширине 40 столбцов.

Отдельная проверка понятности проводится с человеком, ранее не работавшим
с Mors: из главного меню без подсказок разработчика добавить подключение,
исправить неудачную проверку, оставить резервом, временно исключить и удалить
выбранное подключение. Человек до подтверждения должен суметь объяснить,
что удалится, что продолжит работать и чем удаление отличается от остановки.
Критерии: не требуется вводить известные системе имена/ID или искать синтаксис,
нет тупика после ошибки, нет ошибочного удаления, последствия поняты правильно.
Затруднения фиксируются и исправляются до приёмки; эта проверка с пользователем
ещё не проведена. Документальный просмотр не доказывает удобство готового CLI.

Документальная проверка #65: сверка с #58/#62, актуальным dispatch/help,
локальными ссылками и `git diff --check`. Таблица выше задаёт будущие
исполняемые тесты, а не отчёт об их прохождении. Реализация и fixtures CLI —
