# Требования к общему ядру и пулу подключений Mors

Статус: согласованный продуктовый контракт, реализация предстоит. Основание —
[issue #58](https://github.com/ivni/mors/issues/58), результаты интервью
13.09.2026. Документ фиксирует требования, а не объявляет новые возможности
доступными. Проверенная исходная версия `main`:
`bbc8461b56675203b6c99581d609ad09d1888fdb` (включает исправление #57).

## Границы и источники

Цель — один управляемый из Mors пул VPN с общей логикой здоровья, выбора и
безопасных изменений. Пользователь должен пройти путь от добавления до
проверенного результата и самостоятельно понять причину неудачи.

В #58 создаётся только этот документ: без изменения runtime, пакета, роутера
или реализации последующих задач. Требования ниже обязательны для перехода;
методы их будущей проверки не означают, что проверки уже выполнены.
Идентификаторы `REQ-CORE-NNN` стабильны и не переиспользуются.

Источники действующих правил:

- [AGENTS.md](../AGENTS.md) — платформа, границы изменений и выпуск;
- [дизайн-система CLI](cli-design-system.md) — термины, состояния, подтверждения,
  ошибки и JSON;
- [VLESS-архитектура](vless-architecture.md) — исходная семантика здоровья,
  sticky-выбора, supervisor и границы Xray;
- [lifecycle-архитектура](lifecycle-architecture.md) — транзакции, владение,
  backup, rollback и восстановление;
- [архитектура телеметрии](telemetry-architecture.md) — opt-in, закрытый список
  экспортируемых данных и безопасный жизненный цикл.

Issue #58 определяет целевой продуктовый результат. Перечисленные документы
остаются контрактами действующей реализации; их протокольные детали нельзя
механически распространить на всё ядро. Новые UX-паттерны сначала уточняются в
дизайн-системе в #65. Применимые `PRINC-ID`: —; AGENTS.md не задаёт таких ID,
поэтому здесь используются ссылки на нормативные документы.

Сверка выполнена по указанному SHA, чтением документов и кода; роутерные
свойства и будущая реализация этим не доказаны.

Нельзя тиражировать независимый supervisor по протоколам: это оставит конкурирующих владельцев маршрута. Границы общего ядра решаются в #62. Лимит четырёх VLESS не становится общим лимитом. |

| 008–013 | [CLI-контракт](cli-design-system.md) уже различает состояние, сетевую проверку, подтверждение и принудительный разрыв; конкретные команды относятся преимущественно к VLESS. | Общие команды, названия новых состояний и пределы graceful для разных backend уточняются в #65 и #94; здесь новая CLI-грамматика не вводится. |

| 016–018 | [Телеметрия](telemetry-architecture.md) задаёт opt-in, privacy whitelist и bounded очередь; [vless_runtime](../opt/bin/libs/vless_runtime) разделяет runtime state, active preference и события. | Причинные события общего ядра и снижение I/O требуют отдельных проверок. Путь под `/opt/var/run` сам по себе не доказывает RAM; фактический носитель и записи измеряются. |

Для краткости номера 001–018 в этой таблице означают `REQ-CORE-001`–
`REQ-CORE-018`. Существующие BATS в [tests](../tests) дают исходные сценарии,
но не заменяют будущие межпротокольные и платформенные проверки.

## Неопределённости и безопасные инженерные defaults

Это маршруты дальнейшего исследования, а не дополнительные согласованные
обещания. Ответственность за закрытие несёт исполнитель указанного issue.

| Вопрос | Где закрывается | До получения доказательств |
| --- | --- | --- |
| Фактические модели/ABI/OS-компоненты и пределы ресурсов | [#59](https://github.com/ivni/mors/issues/59), [#60](https://github.com/ivni/mors/issues/60), [#117](https://github.com/ivni/mors/issues/117) | Сохранить требование текущей поддержки; не обещать универсальный бинарник и не исключать платформу без решения. |
| Способ исполнения Hysteria 2 и точка интеграции Keenetic | [#61](https://github.com/ivni/mors/issues/61), [#63](https://github.com/ivni/mors/issues/63) | Не выбирать runtime по предположению и не объявлять протокол готовым. |
| API ядра/адаптеров, источник истины при внешней правке, предел пула, алгоритмические настройки | [#62](https://github.com/ivni/mors/issues/62), [#70](https://github.com/ivni/mors/issues/70), [#71](https://github.com/ivni/mors/issues/71), [#93](https://github.com/ivni/mors/issues/93) | Сохранить одного владельца решений и sticky-семантику; не переносить числовые лимиты VLESS на весь пул. |
| Graceful на конкретной паре backend и при редактировании/удалении | [#94](https://github.com/ivni/mors/issues/94), [#115](https://github.com/ivni/mors/issues/115) | Не обещать сохранение сессий без проверки; действие с разрывом только с явным подтверждением. |
| Размещение RAM/durable, batching, потеря событий, численная цель экономии I/O | [#64](https://github.com/ivni/mors/issues/64), [#110](https://github.com/ivni/mors/issues/110), [#111](https://github.com/ivni/mors/issues/111), [#117](https://github.com/ivni/mors/issues/117), [#119](https://github.com/ivni/mors/issues/119) | Не обещать процент экономии; не переносить recovery и значимые события только в RAM и не ослаблять сохранность молча. |

Переход сохраняет текущую IPv4-границу. Балансировка новых сессий по нескольким
активным выходам, автоматическая установка OS-компонентов и перенос произвольных
живых сессий при аварии в согласованный объём не входят.

- Все восемь пунктов приёмки исходного issue отражены: пул — 001–003;
  выбор — 004–005; Rust/роутеры — 006–007; UX — 008–009;

  [gate #121](https://github.com/ivni/mors/issues/121).
